# Preserve & restore diagnostic/treesitter state instead of forcing it

- GitHub Issue: #1

## Problem

When a conflict is detected/resolved, `detect.lua` unconditionally toggles
diagnostic and Tree-sitter state:

```lua
-- on conflict detected (detect.lua:125-126)
vim.diagnostic.enable(false, { bufnr = bufnr })
pcall(vim.treesitter.stop, bufnr)

-- on conflict resolved / no conflicts (detect.lua:152-153, 116-117)
vim.diagnostic.enable(true, { bufnr = bufnr })
pcall(vim.treesitter.start, bufnr)
```

This assumes the buffer's prior state was "enabled". If the user had already
disabled diagnostics or Tree-sitter for that buffer before a conflict
appeared, resolving the conflict will incorrectly re-enable them.

## Fix

Before disabling, snapshot the current state per-buffer:

```lua
vim.b[bufnr]._conflict_diagnostic_was_enabled = vim.diagnostic.is_enabled({ bufnr = bufnr })
vim.b[bufnr]._conflict_treesitter_was_active = vim.treesitter.highlighter.active[bufnr] ~= nil
```

Then only restore to that captured state when conflicts clear, instead of
always forcing `true`/`start`.

## Affected files

- `lua/conflict/detect.lua`

## Priority

High — this is user-visible side-effect clobbering, flagged as the top issue
in `specs/feedback.md`.
